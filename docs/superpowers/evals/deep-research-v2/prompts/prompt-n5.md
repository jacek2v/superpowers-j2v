Use the superpowers:brainstorming skill: I want notekeep to support syncing notes across a person's devices, with each device able to edit offline and reconcile once it reconnects. Several things are already decided, so don't spend questions on them: the devices never have to talk to each other directly — a passive relay that only stores whatever a device hands it and forwards it on, without interpreting the contents, is perfectly acceptable; a note stays a flat `title` + `body` for now, not finer-grained fields or blocks; assume 2 to 5 devices per person; deleting notes is out of scope for this round; and the relay may keep what it holds until every known device has picked it up. How divergent edits to the same note should be merged, what each device has to retain about a note's change history for that reconciliation to be possible without that record growing without bound, and how a device that has been offline for weeks or is being set up fresh catches up on everything it missed are all open, and multi-device sync is new territory for this project — we have never built anything like it.

Do not hand me those three as three separate answers. They are one architecture choice wearing three hats: whatever settles the merge rule dictates what has to be retained, which in turn dictates how catch-up can work. What I want to see is whole candidate designs put side by side and compared as designs — not a per-question verdict each. I want this settled before we get anywhere near a spec.
